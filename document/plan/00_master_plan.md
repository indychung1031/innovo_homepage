## 5. 이중언어 방식 (확정)

- **기본 언어**: 영어 (English)
- **보조 언어**: 한국어
- **전환 방식**: **URL 분리 방식** (확정) — `/{lang}/페이지명`
  - 영어: `innovosolution.co.kr/en/products`
  - 한국어: `innovosolution.co.kr/ko/products`
  - 루트(`/`) 접속 시 브라우저 언어 감지 후 `/en/` 또는 `/ko/`로 자동 리다이렉트
  - EN/KO 버튼 클릭 시 URL 자체가 변경됨 → 딥링크 공유 가능

- **구현 방식**: HTML 파일은 언어별로 따로 만들지 않음 — 동일한 템플릿 1개 유지
  ```python
  # {lang:en|ko} 정규식 제약 — /admin, /api/, /static/ 등과의 충돌 방지
  @app.get("/{lang:en|ko}/products")
  def get_products(lang: str, request: Request):
      return templates.TemplateResponse("products.html", {"request": request, "lang": lang})
  ```
  - Vanilla JS가 서버에서 넘어온 `lang` 값(또는 `window.location.pathname`)을 읽어 JSON 번역 파일 바인딩
  - 이미지·레이아웃 공통 사용 — 기존 방식과 동일

- **SEO 처리**: 각 URL에 `hreflang` 메타태그 + `<html lang="...">` 속성 적용
  - Googlebot이 `/en/products`와 `/ko/products`를 각각 별도 페이지로 인식·인덱싱
  - 한국어 검색 결과에 `/ko/` URL 노출, 영어 검색 결과에 `/en/` URL 노출

- 가격 계산은 **백엔드(FastAPI) 비즈니스 로직**에서 처리 후 프론트로 전달
  - DB에는 `base_price`(기준가) 하나만 저장
  - **1set(수량 1개) 단가 기준 계산**: 총액 = 적용 단가 × 수량
  - `price_matrix`(수량 × 핀 수 조합 매트릭스)는 1차 오픈 미사용 — 향후 도입 여부 별도 결정
  - 회원 등급별 단가 적용 방식:
    - **인증회원**: `base_price` 그대로 → `discount_rule`(수량 할인) 적용
    - **일반회원**: `base_price × 1.3` 고정 단가 — 수량 할인 없음
- **보안 원칙**: 비회원 API 응답에는 가격 데이터 자체를 포함하지 않음 (프론트에서 숨기는 것이 아닌 API 레벨에서 차단)
